# x402 Allocation Readiness Audit — v0.1 draft

> **Version-stamped snapshot**: This audit is based on the x402 documentation and repository as of **2026-09-07** (x402.org; github.com/x402-foundation/x402, main HEAD). The protocol evolves quickly; conclusions expire with the snapshot. We invite corrections — see [Contributing](../README.md#contributing).

**Layer: payment execution** (value transfer). This audit asks one question of x402: when value flows through the protocol, does it carry any rule for how that value is *divided* among the parties that produced it — humans, agents, data providers, models, infrastructure? Attribution (who paid, who executed) is well addressed; allocation is the gap. We do not rank x402 against authorization-layer protocols (e.g. AP2): different layers, separate audits.

## 2. Evidence check

| # | Claim | Evidence status | Notes |
|---|---|---|---|
| X2 | Zero protocol fees | **Verifiable, now with two independently checkable layers** | Protocol layer: no fee is charged by the standard itself. Facilitator layer: pricing is public and commercial — the Coinbase Developer Platform facilitator charges $0.001 per onchain transaction after 1,000 free per month, with verification always free (X9). Fees exist but are transparent, capped per-transaction, and avoidable entirely (self-facilitation is a documented path, X7). |
| X4 | Trust minimizing | **Verifiable by design at execution layer** | Payment schemes (`exact`, `upto`, `batch-settlement` — GitHub README, snapshot 2026-09-07) are specified so facilitators cannot move funds beyond client intent; the facilitator "does not hold funds or act as a custodian" (X8). This is fund safety during transfer, not a rule for dividing produced value. |
| X5, X7 | Network-agnostic; facilitator plurality | **Verifiable** | Multi-chain SDKs are shipped in the reference repository; running your own facilitator or self-facilitating inside the resource server is a documented production path. This is strong evidence the execution layer has no single mandatory chokepoint. |
| X1 | Open, neutral standard | **Partially verifiable** | x402 is a Linux Foundation project ("Copyright © x402 a Series of LF Projects, LLC" — x402.org footer, snapshot 2026-09-07). The technical specification's authorship, however, is concentrated: the whitepaper is authored by the Coinbase Developer Platform / x402 team (x402-whitepaper.pdf, May 2025). Governance internals (member composition, admission, independence of the originating company) remain not independently checkable from public governance documents we have reviewed; see gap G4. |
| — | Allocation rule | **Absent by inspection** | Across the claims above and the scheme specifications reviewed, no mechanism defines how the value transferred should be split among contributing parties. No allocation constraint type, no value-split extension, no revenue-division primitive appears in the reviewed material. |

## 3. ARL assessment (allocation dimension)

> Classification rule (from the methodology): a system is classified **by the first question it fails**, not forced onto the nearest rank.

**x402, in the value-allocation dimension: ARL 0.**

- **ARL 0** — "No allocation rule exists; value is captured by whoever controls the interface."
- Basis: x402 defines who *pays* and who *executes* (client → resource server, via facilitator), and defines this well. It defines nothing about how value produced jointly by humans, agents, data, models, and infrastructure should be *divided*. With no allocation rule, the division defaults to whoever controls the interface (resource server pricing, facilitator fee-setting) — precisely the ARL 0 condition.

**Read this correctly.** ARL 0 on allocation is not a verdict that x402 fails at its own job. As a payment *execution* layer, x402 is genuinely strong: fund safety by design (X4), no single mandatory facilitator (X7), multi-network reach (X5), real economic usage. The finding is scoping, not condemnation: **x402 answers "who pays whom" and leaves "who deserves what share" to layers it does not govern.** That residual question is what this project tracks.

## 4. Gap list (what would raise the allocation-dimension level)

| Gap | To reach | Description |
|---|---|---|
| G1 | ARL 1 (rule exists) | Any normative allocation rule or primitive: a value-split scheme, an allocation constraint type, a revenue-division extension point in the spec. Currently absent. |
| G2 | Facilitator-layer economics | **Largely closed for the incumbent facilitator** (public CDP pricing, X9), open for the ecosystem: whether a market of facilitators with divergent fee structures emerges, and whether fee-setting remains verifiable as the ecosystem scales. |
| G3 | ARL 2→3 | If an allocation rule is added: it must be independently verifiable and usable by heterogeneous parties (human sellers, agent operators, data licensors) — not a single operator's private ledger. |
| G4 | Governance evidence | Publish or point to governance documents that make "open, neutral standard" (X1) independently checkable: member list, admission criteria, and the governance relationship between the Linux Foundation project and Coinbase (the whitepaper's author). (Evidence currently insufficient.) |

## 5. Ecosystem reality check: settlement authenticity (case study)


Agentic commerce — AI agents paying for APIs, data, and compute autonomously — has been
declared "arrived" based on headline metrics: 160+ million settlements on the x402 protocol,
backed by Coinbase, Cloudflare, Google, Stripe and Visa under Linux Foundation governance.

Population-scale measurement tells a different story. The first academic audit
(arXiv:2607.12575, July 2026) found that of 136.7M settlements ($44.1M) on Base over 280 days:

- 21.20% are provably fictitious;
- 63.78% are internal settlement within linked clusters (self-dealing);
- genuinely independent demand is bounded between $187,861 and $20,258,746 — a 100x uncertainty
  interval that no current infrastructure can narrow.

Settlement count, the ecosystem's headline metric, measures *manufacturability*, not adoption:
gas is sponsored, nothing on-chain marks who controls a payment, and a manufactured settlement
is indistinguishable from genuine demand at the single-transfer level.

Security research compounds the gap. The first systematic study of 15 real-world facilitators
(USENIX Security 2026, covering 60K sellers / 360K buyers) demonstrates four novel attack
vectors: Free Shopping, Asset Theft, Service Denial, and Gas Abuse. Meanwhile price integrity
fails independently of fraud — 4.4% of 4,251 catalogued routes quote a live price that differs
from the listed price, with tail cases off by 100-1000x (TOLL·402, August 2026).

### Why this matters beyond crypto

Agentic commerce is inheriting the internet's trust infrastructure from scratch — without the
consumer protection layer that took decades to build around card payments. Journalists and
legal analysts (Forbes, Bloomberg Law, Mondaq, August 2026) have already flagged the
chargeback liability gap: when an AI agent buys the wrong thing, no one can prove who
authorized what. The x402 case demonstrates a pattern MECIP has documented across the AI
economy: **adoption metrics that cannot be manufactured are the precondition for trustworthy
ecosystems — and they do not yet exist here.**

### What independent audit infrastructure would look like (research agenda)

1. Reproducible authenticity scoring (payment-graph clustering + cohort signals, per
   arXiv:2607.12575's method, as open tooling rather than a one-off paper);
2. Facilitator security benchmarking (extending x402scope's attack taxonomy);
3. Price-integrity monitoring (catalogued vs. live quote drift, per TOLL·402);
4. Agent reputation audit bridging ERC-8004 registries to independent verification.

This section will be updated as MECIP's related open-source work progresses.

### Independent replication (September 2026)

As a first step toward open audit infrastructure, we independently replicated the
population-scale methodology on the Tektonic x402 CC0 public dataset (BigQuery,
Analytics Hub), covering 52,723,702 USDC settlements ($8.98M) on Base from
2025-12-05 to 2026-04-14 — the protocol's explosive-growth window.

Preliminary aggregated findings (full addresses withheld; aggregate statistics only):

- **Gini coefficient of payer activity: 0.9673** — directionally consistent with the
  paper's >0.98 across all measured dimensions; extreme concentration is confirmed
  by an independent dataset and pipeline.
- **Nakamoto coefficient: 330 payers (0.42% of all payers) control 50% of all
  settlement count.** The "agent economy" on Base is, by count, an economy of a few
  hundred operational wallets.
- Facilitator-level concentration is visible at the aggregate level: the largest
  facilitator accounts for ~55% of settlement count; several mid-size facilitators
  show sink-structure signatures (hundreds of thousands of settlements toward a
  single-digit number of recipients) and near-zero per-call value — patterns
  consistent with the manufacturable component the paper describes.

Replication status: pipeline v0 (aggregation stage) reproduces the paper's headline
concentration findings; cluster-assignment (C1/C2/C3) replication is in progress.
All tooling and queries will be released as open source.
## 6. Method & limitations

- Sources: x402.org (homepage, FAQ), the x402-foundation/x402 GitHub repository (README, main HEAD), docs.x402.org (facilitator page), and the Coinbase Developer Platform x402 facilitator documentation (pricing), all as of snapshot 2026-09-07. The whitepaper was reviewed for authorship; the full `specs/` tree was reviewed only for the claims listed — absence findings are scoped to reviewed material. If an allocation primitive exists elsewhere in the spec, this audit wants to know (open an issue).
- "ARL 0" here applies to the **allocation dimension of the payment-execution layer**. It does not measure x402's execution-layer quality, security, or adoption.
- Evidence marked "insufficient" was not treated as absence. Gap G4 remains open until evidence is provided; G2 is closed for the incumbent facilitator (public pricing) and open for the broader facilitator ecosystem.
- This methodology is v0.1 and itself expected to change; audits will be re-snapshotted against future protocol versions.
